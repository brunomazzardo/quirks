# QK-SRV-003 Implementation Plan — pairing session, delete the token system

**Goal:** Replace the per-URL viewer/approval token system with one pairing-cookie session, and migrate every token-based test. Owner posture: one auth moment, then the client trusts the local API — no second credential system.

**Prereq:** QK-SRV-002 (daemon) and QK-UI-010/011 landed. Do this on the daemon, not the ephemeral `ui open`.

## Files

**Delete / replace:**
- `src/ui/auth/viewer-session-store.ts` — the URL-token viewer session (8h idle / 24h absolute). Replace with a `pairing-session-store.ts`: pairing-link mint + one-time consume, cookie-session lookup, `unpair`.
- `src/ui/approval/token-store.ts` — the per-open approval token vault. Approval now authorizes off the paired session (the durable digest/replay checks in `open-workspace.ts` `createDurableApprovalWritePort` stay; only the token layer goes).
- `src/ui/client/**` vault/fragment code that reads `#viewToken=` / `qkview_` / `qkapprove_` — replaced by "cookie already set, just call the API".

**Modify:**
- `src/ui/server.ts` / `router.ts` — cookie parsing; `/pair/:link` route sets `Set-Cookie: HttpOnly; SameSite=Strict; Path=/` then 303-redirects to `/`; `/api/*` require a valid session cookie (except `/health`); keep the approval-POST `Origin === authority.origin` check exactly as-is.
- `src/cli/quirks-campaign.ts` (`ui open`) → becomes a daemon-attach alias that prints the pairing link on first pair.
- `schemas/ui-approval-request-v1.schema.json` (drop required `approvalToken`) and `schemas/campaign-approval-v1.schema.json` (replace required `tokenId` with a session-identity field; existing entries with `tokenId` remain readable by `hasDurableApproval`). Regenerate validators.
- `AGENTS.md` UI section + founding spec §12/§20: recalibrate to loopback + pairing cookie + honest journaling (the "credentials never in cookies" rule and byte-diff security-review language relax for local UI).

**Test-harness migration (the big surface — do it as its own step):**
- `test/browser/support/launch-ui.ts` — `viewerUrl()` boots every browser spec via the `#viewToken=` fragment. Replace with a pairing bootstrap (hit `/pair/<link>`, follow the Set-Cookie).
- `test/ui/auth/**`, `test/ui/approval/**`, `test/ui/security/api-abuse.test.ts`, all `test/ui/api/*.test.ts` — migrate from issued bearer/fragment tokens to cookie sessions.
- Recorded supersession: the `read-only-workspace` 409 token tests give way to the campaign-status gate.

## Steps (TDD, per unit)

1. `pairing-session-store` unit: mint link (TTL, single atomic consume), cookie lookup, `unpair` revokes all, secret hashed 0600 survives a restart. Red → implement → green → commit.
2. Router: `/pair` sets cookie + 303; `/api/*` 401 without cookie (except `/health`); approval-POST Origin check unchanged (assert it still rejects a wrong Origin). Red → green → commit.
3. Delete `viewer-session-store` + `token-store` + client fragment/vault; wire the cookie path. `grep -R 'viewToken|approvalToken|qkview_|qkapprove_|token-vault' src/` returns nothing. Commit.
4. Schema evolution + validator regen; `hasDurableApproval` still reads legacy `tokenId` entries. Commit.
5. Migrate the browser + api + auth + approval + api-abuse suites to the pairing bootstrap; delete the superseded 409 token tests with a note. Commit.
6. AGENTS.md / founding-spec recalibration in this same change. Commit.
7. `pnpm check` + `npx playwright test` green; `git diff --check` clean.

## Invariants to preserve
- Loopback-only bind, nonce-CSP, no remote assets unchanged.
- Approval stays digest-bound: envelope re-read + replay check at consume, durable journaling — untouched.
- `unpair` is a real kill-switch (next request 401s).
