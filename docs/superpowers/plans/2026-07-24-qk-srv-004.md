# QK-SRV-004 Implementation Plan — global multi-repo registry + scoping

**Goal:** One standing server serves every registered quirks repo — current tasks, past and live campaigns — with reads strictly scoped server-side to the requested repo. Generalizes the QK-UI-005 standalone scoping; the security-sensitive part is that scoping must be leak-proof (the QK-UI-005 review already found and fixed one cross-repo disclosure).

**Prereq:** QK-SRV-003 (pairing session).

## Files

- **New** `src/ui/repo-registry.ts` — durable registry under the `resolveAppPaths` state dir: `{ repositoryId, root, addedAt }[]`. `register(root)` (auto on `quirks ui` in a repo), `deregister(root)`, `list()`. Registry mutations are CLI-only; **no HTTP route mutates the registry.**
- Modify `src/ui/open-workspace.ts` — today it binds one `repositoryRoot`; generalize so the server holds N registered repos and resolves per-request. Reuse `createStandaloneWorkspacePorts` / `listRepositoryCampaigns` per repo.
- Modify `src/ui/router.ts` + `src/ui/api/*` — every read route takes a `repositoryId`; it **must be in the registry**; the filesystem path comes from the registry entry, **never derived from the request** (client `repositoryId` is only a registry key). Unregistered repo → 404 fail-closed **even if its state exists on disk** under `repositories/`.
- Modify `src/ui/client/routes/root.tsx` (nav) — repository switcher; a unified cross-repo **Active** campaigns strip (aggregate registry members, each item carrying its repositoryId).
- CLI: `quirks ui add-repo <path>` / `remove-repo <path>` in `src/cli/quirks-campaign.ts`.

## Steps (TDD)

1. `repo-registry` unit: register/deregister/list, dedupe by repositoryId, durable across restart. Red → green → commit.
2. Per-request scoping in the ports/router: requested repositoryId resolved through the registry entry's root only. Red → green → commit.
3. **Cross-repo leak tests, QK-UI-005 falsification style:** two-repo fixture; assert every read route (campaigns list/detail, existing-tasks, task-history, prompts, preflight, plan-progress) returns only the requested repo's data and 404s an unregistered repo whose state exists on disk. Reverting the scoping must make these fail. Commit.
4. Repo switcher nav + unified Active strip; each active item labeled with its repositoryId. Playwright with a two-repo fixture. Commit.
5. Dead/unmounted registered root → honest per-repo "unavailable" without failing other repos or the daemon. Commit.
6. `add-repo`/`remove-repo` CLI; `remove-repo` takes immediate effect on reads (and, once QK-SRV-007 lands, tears down that repo's watcher). Commit.
7. `pnpm check` + `npx playwright test` green.

## Invariants
- A paired session may read any **registered** repo — that is the whole authority boundary (single-user tool).
- No request input ever becomes a filesystem path; the registry is the only path source.
- Registry is CLI-mutated only; the HTTP surface is read-only over it.
